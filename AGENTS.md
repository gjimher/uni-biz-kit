# Codex-specific instructions

* **Architecture and environment decisions require explicit approval:** do not make or silently fold architectural or environment decisions into an approved implementation. This includes process or container topology, frameworks or major dependencies, public model/schema/API contracts, authentication or authorization design, deployment strategy, generator boundaries, and environment configuration. Diagnose the issue, explain the concrete options and trade-offs, recommend one, and wait for the user to choose or explicitly approve the recommendation. An approved feature or bug-fix plan authorizes ordinary implementation details only; its plan must call out any decision in this category separately. Read-only diagnosis is allowed.
* **Generated-code assertions are temporary by default:** do not finish a task with tests that assert generated source fragments, SQL text, internal `_` metadata, filenames, import paths, component names, exported symbols, or other implementation identifiers. Use them only while developing, then remove them before handoff. A permanent exception requires explicit user approval and a comment naming the external consumer or non-obvious compatibility contract it protects. Before reporting completion, review the test diff specifically for these assertions. Prefer observable E2E, API, or database behavior and compilation.
